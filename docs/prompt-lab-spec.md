# Prompt Lab — 진로 연계형 AI 프롬프트 학습 웹사이트 개발 기획서

## 1. 프로젝트 개요

중학교 3학년 학생을 대상으로 진행하는 진로 연계형 AI 바이브 코딩 교육에 활용할 전문적인 웹사이트를 개발한다.

서비스명은 가칭 **Prompt Lab(프롬프트 랩)**으로 한다.

본 웹사이트는 단순히 앱을 개발하거나 Canva AI의 사용법을 알려주는 교육 플랫폼이 아니다. 학생들이 자신의 생각을 구체화하고, AI에게 의도를 정확하게 전달하며, 결과물을 확인하고 개선하는 프롬프트 작성 역량을 기르는 것을 목적으로 한다.

웹사이트 자체도 바이브 코딩을 통해 개발하며, 강의에서 해당 사실과 실제 제작 과정을 공개하여 학생들의 흥미와 동기를 유발한다.

학생들이 직접 사용하는 웹사이트를 통해 코딩 경험이 없어도 자신의 아이디어와 AI를 활용하여 높은 완성도의 결과물을 만들 수 있다는 가능성을 체감하도록 한다.

### 핵심 슬로건

**같은 아이디어, 다른 프롬프트, 다른 결과물.**

### 서비스 정의

Prompt Lab은 학생이 자신의 아이디어를 직접 프롬프트로 작성하고, AI와 함께 이를 구체적인 개발 요구사항으로 발전시키며, 각 프롬프트에서 생성된 실제 결과물을 비교하여 AI 활용 역량을 기를 수 있도록 설계된 진로 연계형 학습 웹사이트다.

## 2. 교육 대상 및 목적

### 교육 개요

- 교육 대상: 중학교 3학년
- 교육 시간: 총 2차시, 차시당 60분
- 교육 방식: 진로 연계형 바이브 코딩 실습
- 최종 앱 제작 도구: Canva AI의 Canva Code
- 학생의 사전 개발 경험: 없음을 전제로 함
- 주요 실습 환경: 학교 PC 및 노트북
- 교육용 웹사이트: Prompt Lab

### 핵심 교육 목표

학생들이 졸업 이후에도 다양한 직업과 일상생활에서 활용할 수 있는 범용적인 프롬프트 작성 역량을 기르는 것이 최우선 목표다.

앱 개발은 교육의 최종 목적이 아니라 자신이 작성한 프롬프트의 가치와 영향력을 시각적으로 체험하기 위한 수단이다.

학생들이 미래에 개발자가 되지 않더라도 자신의 관심 분야와 직업에서 AI를 효과적으로 활용할 수 있도록 한다.

### 두 가지 핵심 교육 역량

**첫 번째: 프롬프트 작성 역량**

자신이 원하는 결과물을 구체적으로 생각하고 AI가 이해할 수 있도록 명확하게 설명하는 능력이다.

**두 번째: AI 협업 역량**

자신이 작성한 내용을 AI와 함께 발전시키고, AI의 결과물을 검토하며 부족한 부분을 개선하는 능력이다.

### 학생의 학습 과정

1. 자신의 관심 분야와 관련된 문제를 발견한다.
2. 좋은 프롬프트를 작성하는 기본 원칙을 학습한다.
3. 학습한 원칙을 바탕으로 자신이 만들고 싶은 앱을 자유롭게 설명한다.
4. AI와 함께 자신의 프롬프트를 구체화한다.
5. 최초 프롬프트와 개선된 프롬프트의 차이를 이해한다.
6. 두 프롬프트에 따른 실제 결과물을 비교한다.
7. 결과물을 검토하고 부족한 부분을 개선한다.
8. 최종 프롬프트를 활용해 Canva Code로 앱을 제작한다.
9. 이러한 경험을 자신의 미래 진로와 연결한다.

## 5. Learn — 프롬프트 배우기

중학생이 쉽게 이해할 수 있도록 프롬프트 작성법을 간결하고 시각적으로 설명한다.

전체 이론 학습 분량은 약 10분 이내로 구성한다.

### 5-1. 프롬프트 작성의 5가지 핵심 요소

**① 목적(Why)**

왜 만들고 싶은가?

예시: 매일 운동한 시간을 기록하고 꾸준히 운동하는 습관을 만들고 싶다.

**② 대상(Who)**

누가 사용할 것인가?

예시: 운동을 좋아하거나 운동을 처음 시작하는 청소년.

**③ 기능(What)**

무엇을 할 수 있어야 하는가?

예시: 운동 기록, 운동 목표 설정, 주간 운동 통계.

**④ 디자인(How)**

어떤 모습과 방식으로 만들 것인가?

예시: 검은색과 초록색을 활용한 스포티한 디자인.

**⑤ 조건(Rules)**

반드시 지켜야 할 기준은 무엇인가?

예시: 모든 버튼이 실제로 작동하고 모바일에서도 사용할 수 있어야 한다.

### 범용적인 AI 활용 역량과의 연결

이러한 작성 원칙은 앱 개발에만 적용되는 것이 아님을 설명한다.

다음과 같은 다양한 상황에서도 활용할 수 있도록 안내한다.

- 학교 보고서 작성
- 발표자료 제작
- 디자인 및 콘텐츠 제작
- 자료 조사
- 진로 탐색
- 여행 계획 수립
- 업무 자동화
- 제품 및 서비스 기획

학생들이 다섯 가지 요소를 반드시 정해진 형식으로 작성해야 한다고 느끼지 않도록 한다.

자연스럽게 자신의 생각을 설명하되 필요한 내용이 포함되어 있는지 확인하는 기준으로 활용하도록 지도한다.

## 6. 프롬프트 발전 과정 3단계 비교

프롬프트 작성법을 설명하는 과정에서 동일한 아이디어를 세 가지 수준의 프롬프트로 작성하고, 실제 생성된 결과물을 비교하여 보여준다.

해당 비교 사례는 강사가 수업 전에 사전 제작한다.

### Level 1. 일반적인 프롬프트

프롬프트 작성법을 학습하기 전, 일반적으로 AI에게 요청하는 방식이다.

**프롬프트 예시**

운동 기록 앱 만들어줘.

### Level 2. 5가지 요소를 적용한 프롬프트

학생이 프롬프트 작성 원칙을 학습한 후 직접 작성할 수 있는 수준이다.

**프롬프트 예시**

운동을 좋아하는 학생들이 꾸준히 운동하는 습관을 만들 수 있도록 앱을 만들어줘.

운동 시간을 기록하고 하루 운동 목표를 설정할 수 있으면 좋겠어.

운동한 내용을 그래프로 보여주고 운동할 때마다 포인트도 줬으면 좋겠어.

검은색과 초록색을 사용해서 멋있게 만들어줘.

모든 버튼이 실제로 작동하고 스마트폰에서도 사용할 수 있게 해줘.

### Level 3. AI와 함께 발전시킨 프롬프트

5가지 핵심 요소가 포함된 학생의 프롬프트를 바탕으로 기능의 구체적인 작동 방식과 화면 구성, 데이터 변화, 예외 처리 등을 보완한다.

**프롬프트 예시**

운동 습관을 형성하고 싶은 청소년을 위한 게임형 운동 기록 웹앱을 만들어줘.

제작 목적은 사용자가 매일 자신의 운동량을 확인하고 목표를 달성하면서 꾸준히 운동하도록 동기를 부여하는 것이다.

**운동 기록 기능**

- 운동 종류, 날짜, 운동 시간을 입력한다.
- 등록한 운동 기록을 수정하거나 삭제할 수 있도록 한다.
- 기록이 변경되면 총 운동 시간이 즉시 업데이트된다.

**목표 관리 기능**

- 사용자가 하루 운동 목표 시간을 직접 설정할 수 있도록 한다.
- 실제 운동 시간과 목표 시간을 비교하여 달성률을 계산한다.
- 목표 달성률을 프로그레스 바로 표시한다.

**보상 시스템**

- 운동 10분당 10포인트를 지급한다.
- 누적 100포인트마다 레벨이 상승하도록 한다.
- 운동 기록을 수정하거나 삭제하면 포인트도 다시 계산한다.

**통계 및 화면 구성**

- 홈 화면에 오늘의 운동 시간, 목표 달성률, 현재 레벨을 표시한다.
- 최근 7일간의 운동 시간을 막대그래프로 보여준다.
- 운동 기록이 변경되면 통계도 즉시 반영한다.

**디자인**

- 검은색 배경과 네온 그린 포인트 컬러를 적용한다.
- 스포티하고 세련된 모바일 중심 디자인을 구현한다.

**구현 조건**

- 모든 버튼이 실제로 작동하도록 한다.
- 음수나 잘못된 운동 시간을 입력하지 못하도록 검증한다.
- 개인정보 입력 없이 사용할 수 있도록 한다.
- 전체 인터페이스는 한국어로 구성한다.

포인트 지급 기준 등 학생이 직접 정하지 않은 내용은 AI가 제안한 기본값임을 표시하고 학생이 수정할 수 있도록 한다.

### 6-1. 단계별 비교의 핵심

**Level 1 → Level 2**

목적, 대상, 기능, 디자인, 조건을 명확하게 설명하는 것의 중요성을 학습한다.

**Level 2 → Level 3**

기능의 구체적인 작동 방식, 기능 간의 관계, 화면 구성 및 예외 상황까지 고려하는 것의 중요성을 학습한다.

Level 2는 부족하거나 잘못된 프롬프트가 아니다.

학생이 직접 작성한 좋은 프롬프트를 AI와 함께 더욱 발전시키는 과정으로 Level 3을 설명한다.

### 6-2. 비교 화면 구성

세 가지 프롬프트와 각각의 실제 생성 결과물을 함께 보여준다.

- Level 1: 일반적인 요청
- Level 2: 핵심 요소가 적용된 요청
- Level 3: AI와 함께 구체화한 요청

데스크톱에서는 3분할 레이아웃 또는 비교 탭을 제공한다.

모바일에서는 단계별 결과물을 전환하여 확인할 수 있도록 한다.

각 결과물은 실제로 버튼을 누르고 기능을 체험할 수 있는 간단한 웹앱으로 구성한다.

사전 제작된 결과물은 수업 중 별도의 API 호출 없이 즉시 실행할 수 있도록 한다.

### 6-3. 학생 실습과의 구분

강사의 설명 과정에서는 Level 1, Level 2, Level 3의 세 가지 결과물을 모두 비교한다.

학생 개인 실습에서는 다음 두 가지 결과물만 실시간으로 생성한다.

- Before: 5가지 요소를 학습한 후 학생이 직접 작성한 프롬프트
- After: 학생의 프롬프트를 AI와 함께 발전시킨 프롬프트

학생 개인별로 Level 1 결과물까지 생성하지 않는다.

이를 통해 교육 효과를 유지하면서 API 비용과 생성 대기 시간을 줄인다.

## 8. Studio — AI 프롬프트 실험실

본 웹사이트의 가장 핵심적인 기능이다.

학생이 만들고 싶은 앱을 일상적인 언어로 자유롭게 설명하면 LLM API를 활용하여 해당 내용을 분석하고 실제 앱 개발에 적합한 프롬프트로 발전시킨다.

### 8-1. 자유로운 아이디어 입력

학생들은 Learn 페이지에서 학습한 5가지 핵심 요소를 참고하여 자신이 만들고 싶은 앱을 자유롭게 설명한다.

복잡한 기획서나 정해진 입력 양식 작성을 강제하지 않는다.

ChatGPT와 대화하듯 자연스럽게 자신의 생각을 서술할 수 있는 인터페이스를 제공한다.

**학생 입력 예시**

나는 운동을 좋아하는데 학생들이 꾸준히 운동할 수 있도록 운동 기록 앱을 만들고 싶어. 운동한 시간을 기록하고 목표 달성하면 레벨업도 하고 게임처럼 포인트도 받으면 좋겠어. 일주일 동안 운동한 내용도 그래프로 보고 싶고 검은색에 초록색 느낌이면 좋겠어. 스마트폰에서도 모든 버튼이 잘 작동했으면 좋겠어.

학생의 최초 입력은 수정하지 않고 원본으로 유지한다.

### 8-2. 프롬프트 작성 가이드

입력창 주변에 프롬프트 작성의 5가지 핵심 요소를 간단하게 표시한다.

- 목적
- 대상
- 기능
- 디자인
- 조건

학생들이 작성 중에도 앞서 학습한 내용을 쉽게 떠올릴 수 있도록 한다.

다만 각 요소를 입력했는지 여부에 따라 작성이나 생성을 강제로 제한하지 않는다.

학생의 자연스러운 아이디어 표현을 우선한다.

### 8-3. AI 프롬프트 개선

LLM API를 활용하여 학생의 입력을 분석한다.

단순히 문장을 전문적으로 바꾸거나 프롬프트를 길게 만드는 것이 아니라 실제 결과물의 완성도와 사용성을 높일 수 있도록 구체화한다.

다음 요소를 중심으로 분석하고 필요한 부분을 보완한다.

- 앱의 제작 목적
- 주요 사용자
- 해결하려는 문제
- 핵심 기능의 작동 방식
- 사용자 행동에 따른 화면 및 데이터 변화
- 기능 간의 연관성과 처리 규칙
- 화면 구성 및 사용자 이동 흐름
- 디자인 및 사용자 경험
- 잘못된 입력과 예외 상황 처리
- 정상적인 결과물 구현을 위한 조건

### 8-4. AI 개선의 구체적인 기준

다음과 같은 방식으로 기존 요구사항을 발전시킨다.

**기능의 구체화**

운동 시간을 기록한다.

→ 운동 종류, 시간, 날짜를 입력하고 기록을 수정하거나 삭제할 수 있도록 한다.

**계산 및 처리 규칙의 구체화**

운동하면 포인트를 지급한다.

→ 운동 10분당 10포인트를 지급하고 누적 100포인트마다 레벨업한다.

**기능 간 관계의 구체화**

운동 기록과 통계를 제공한다.

→ 운동 기록을 수정하거나 삭제하면 총 운동 시간, 목표 달성률, 통계가 즉시 변경된다.

**화면 구성의 구체화**

운동 관리 앱을 만든다.

→ 홈 화면에는 오늘의 운동 시간과 목표 달성률을 표시하고 기록 화면에서는 운동 내역을 관리한다.

**디자인의 구체화**

멋있게 만들어줘.

→ 검은색 배경, 네온 그린 포인트 컬러, 카드형 대시보드, 모바일 중심 레이아웃을 적용한다.

**예외 상황의 구체화**

모든 버튼이 작동하게 해줘.

→ 잘못된 입력값을 검증하고 기록이 없는 상태에서도 정상적인 화면을 표시한다.

### 8-5. 개선 과정의 제한 사항

AI는 학생의 원래 아이디어를 최대한 유지한다.

학생이 요청하지 않은 복잡한 기능을 무분별하게 추가하지 않는다.

기존 기능을 구체적으로 설계하는 것을 새로운 기능 추가보다 우선한다.

학생이 명시하지 않은 세부 사항은 합리적인 기본값 또는 개선 제안으로 구분한다.

필요한 경우에만 최대 1~2개의 추가 질문을 제공한다.

추가 질문에 답하지 않아도 기본값을 적용하여 진행할 수 있도록 한다.

이미 충분히 구체적인 프롬프트라면 불필요한 내용을 추가하지 않는다.

학생이 잘 작성한 부분을 인정하고 실제로 보완할 필요가 있는 내용만 개선한다.

불필요하게 구현 난이도를 높이지 마세요.

학생이 답변하지 않아도 합리적인 기본값을 적용해 진행할 수 있도록 하세요.

이미 충분히 구체적인 프롬프트라면 불필요한 개선을 하지 말고 잘 작성된 부분을 설명하세요.

최종 프롬프트는 Canva Code와 같은 자연어 기반 웹앱 제작 도구에 바로 입력할 수 있는 명확한 형태로 작성하세요.

개선 이유는 중학생도 이해할 수 있도록 쉽고 구체적인 한국어로 설명하세요.

학생이 작성한 프롬프트보다 AI가 작성한 프롬프트가 반드시 우수하다고 주장하지 마세요.

교육 목적은 학생이 스스로 좋은 프롬프트를 작성하고 AI를 효과적으로 활용할 수 있도록 돕는 것입니다.

### LLM 응답 구성

프론트엔드에서 결과를 안정적으로 표시할 수 있도록 구조화된 응답을 사용한다.

다음 정보를 포함한다.

- originalPrompt: 학생이 작성한 최초 프롬프트
- improvedPrompt: AI가 발전시킨 프롬프트
- strengths: 학생이 잘 작성한 부분
- improvements: 개선된 내용과 개선 이유
- assumptions: AI가 적용한 기본값 및 제안
- followUpQuestions: 필요한 추가 질문
- learningSummary: 학생이 학습할 수 있는 핵심 내용

가능한 경우 JSON Schema 기반 구조화된 응답을 적용한다.

## 10. Before & After & Why 프롬프트 비교

AI 프롬프트 개선 결과를 다음 세 가지 영역으로 구성한다.

### Before — 내가 작성한 프롬프트

학생이 5가지 요소를 학습한 후 직접 작성한 원문을 그대로 보여준다.

### After — AI와 함께 발전시킨 프롬프트

AI가 학생의 의도를 유지하면서 구체적인 개발 요구사항으로 발전시킨 프롬프트를 보여준다.

학생이 직접 수정할 수 있도록 편집 기능을 제공한다.

### Why — 무엇이 달라졌을까?

프롬프트가 어떻게 개선되었는지 중학생이 이해할 수 있도록 설명한다.

다음 내용을 포함한다.

- 학생이 처음부터 잘 작성한 부분
- 부족하거나 모호했던 부분
- AI가 구체화한 기능
- 새롭게 정의한 처리 규칙
- AI가 제안한 기본값
- 각 개선 내용이 결과물에 미칠 수 있는 영향
- 학생이 추가로 고민하면 좋은 부분

단순한 프롬프트 평가 점수보다는 실제 개선 내용과 이유를 중심으로 설명한다.

가능한 경우 최초 프롬프트와 개선된 프롬프트의 변경 부분을 시각적으로 강조한다.

학생이 최종 프롬프트를 직접 검토하고 승인한 뒤 결과물 생성 단계로 진행할 수 있도록 한다.

## 11. 실시간 Before & After 결과물 생성

프롬프트 개선의 효과를 시각적으로 체험할 수 있도록 실제 작동하는 미니 웹앱을 생성하는 기능을 구현한다.

학생의 최초 프롬프트와 개선된 프롬프트를 각각 동일한 코드 생성용 LLM에 전달한다.

LLM은 각 프롬프트에 따라 HTML, CSS, JavaScript가 포함된 독립적인 미니 웹앱을 생성한다.

생성된 웹앱은 별도의 배포 과정 없이 현재 웹사이트 내부에서 실행한다.

### 전체 처리 흐름

1. 학생이 프롬프트 작성의 5가지 요소를 학습한다.
2. 학생이 자신의 아이디어를 바탕으로 최초 프롬프트를 작성한다.
3. LLM이 최초 프롬프트를 분석하고 발전시킨다.
4. 학생이 Before, After, Why를 확인한다.
5. 필요한 경우 개선된 프롬프트를 직접 수정한다.
6. 최초 프롬프트와 개선된 프롬프트를 각각 코드 생성 LLM에 전달한다.
7. 두 개의 독립적인 HTML 웹앱을 생성한다.
8. 생성된 결과물을 격리된 iframe 환경에서 실행한다.
9. Before와 After 결과물을 나란히 비교한다.
10. 학생이 두 앱을 직접 조작하고 기능을 테스트한다.
11. 차이점을 확인하고 최종 프롬프트를 수정한다.
12. 최종 프롬프트를 저장하거나 복사한다.
13. 2차시에 Canva Code를 활용해 본격적인 앱을 제작한다.

두 개의 코드 생성 요청은 가능한 경우 병렬로 처리하여 대기 시간을 줄인다.

### 결과물 비교 화면

데스크톱에서는 좌우 2분할 레이아웃을 사용한다.

**왼쪽: Before**

- 학생이 직접 작성한 프롬프트
- 해당 프롬프트에서 생성된 실제 미니 웹앱

**오른쪽: After**

- AI와 함께 발전시킨 프롬프트
- 해당 프롬프트에서 생성된 실제 미니 웹앱

모바일에서는 Before와 After를 전환할 수 있는 탭 형태로 제공한다.

각 결과물은 실제로 작동하는 웹앱이어야 한다.

정적인 이미지나 단순한 UI 목업으로 대체하지 않는다.

학생이 비교에 집중할 수 있도록 프롬프트 내용을 접거나 펼칠 수 있는 기능을 제공한다.

### 결과물 비교 기준

- 제작 목적과 사용자 요구사항 반영 여부
- 핵심 기능 구현 여부
- 기능의 구체적인 작동 방식
- 기능 간 데이터 연동
- 디자인 및 시각적 구성
- 사용 편의성
- 버튼 및 입력 기능의 작동 여부
- 계산 및 처리 규칙의 정확성
- 예외 상황 처리
- 학생의 의도와 결과물의 일치 정도

디자인의 화려함만으로 결과물의 우수성을 판단하지 않는다.

## 12. 결과물 비교의 공정성 및 교육적 해석

### 12-1. 공정한 결과물 생성

최초 프롬프트의 결과물을 의도적으로 낮은 품질로 생성하거나 개선된 프롬프트의 결과물만 화려하게 생성하지 않는다.

두 코드 생성 요청에 다음 조건을 동일하게 적용한다.

- 동일한 LLM 모델 및 모델 버전
- 동일한 시스템 프롬프트
- 동일한 출력 토큰 한도
- 동일한 생성 설정
- 동일한 기술 스택
- 동일한 실행 환경
- 동일한 코드 생성 지침

각각의 사용자 프롬프트만 다르게 전달한다.

코드 생성 모델에는 Before 또는 After라는 구분을 전달하지 않는다.

각 요청은 독립적으로 처리하여 다른 결과물의 영향을 받지 않도록 한다.

강사용 Level 1, Level 2, Level 3 사전 제작 사례에도 동일한 비교 원칙을 적용한다.

### 12-2. 결과물 차이가 크지 않은 경우

학생은 이미 프롬프트 작성의 5가지 핵심 요소를 학습한 상태에서 최초 프롬프트를 작성한다.

따라서 최초 프롬프트의 결과물도 충분히 높은 품질로 생성될 수 있다.

AI로 개선한 프롬프트가 반드시 더 뛰어난 결과물을 생성하는 것은 아니다.

두 결과물의 차이가 작거나 최초 프롬프트의 결과물이 더 좋은 경우에도 이를 교육 실패로 판단하지 않는다.

오히려 학생이 자신의 의도를 충분히 구체적으로 설명했다는 긍정적인 학습 결과일 수 있다.

### 12-3. 결과물 차이에 따른 학습 메시지

**개선된 결과물에서 명확한 차이가 나타난 경우**

기능의 작동 방식과 조건을 더 구체적으로 설명하면 어떤 변화가 나타나는지 확인하도록 한다.

**디자인 차이는 작지만 기능 차이가 나타난 경우**

프롬프트는 외형뿐 아니라 실제 기능의 정확성과 사용성에도 영향을 준다는 사실을 설명한다.

**두 결과물이 비슷한 경우**

학생이 처음부터 충분히 좋은 프롬프트를 작성했을 가능성이 있음을 설명한다.

**최초 결과물이 더 좋은 경우**

AI의 제안이 항상 정답은 아니며 사람이 결과를 직접 판단하고 선택해야 함을 설명한다.

### 12-4. 교육적 해석의 원칙

학생이 실제 두 결과물을 직접 비교하고 판단하도록 한다.

단일 생성 결과만으로 프롬프트의 우수성을 단정하지 않는다.

AI 생성 결과에는 모델의 출력 편차가 존재할 수 있음을 안내한다.

결과물의 차이가 작다는 이유로 의도적으로 최초 결과물의 품질을 낮추거나 개선 결과물만 반복 생성하지 않는다.

웹사이트가 전달해야 할 메시지는 AI가 학생보다 프롬프트를 잘 작성한다는 것이 아니다.

**학생 스스로 좋은 프롬프트를 작성하고 필요할 때 AI와 협업하여 더욱 발전시킬 수 있다는 사실이 핵심이다.**

## 13. 미니 웹앱 생성 범위 및 제한

1차시의 실시간 웹앱 생성은 완성된 상용 서비스를 개발하기 위한 기능이 아니다.

프롬프트 작성 방식에 따른 결과물 차이를 확인하기 위한 간단한 프로토타입 제작 기능이다.

다음 조건으로 생성 범위를 제한한다.

- 핵심 기능 1~3개 중심
- 단일 HTML 파일 기반
- HTML, CSS, Vanilla JavaScript 사용
- 모바일 및 데스크톱 반응형 디자인
- 외부 라이브러리 의존 최소화
- 별도의 백엔드 사용 금지
- 외부 API 연동 제외
- 실제 결제 기능 제외
- 개인정보 수집 금지
- 필요한 경우 가상의 테스트 데이터 사용

세부 기능이 많을 경우 학생에게 주요 기능에 집중하도록 안내한다.

두 결과물에는 동일한 생성 범위와 제한 조건을 적용한다.

1차시의 비교용 미니 웹앱과 2차시 Canva Code에서 제작하는 최종 웹앱의 역할을 명확히 구분한다.

### 코드 생성용 시스템 프롬프트 기본안

사용자가 입력한 요구사항을 바탕으로 실제 작동하는 인터랙티브 미니 웹앱을 제작하세요.

사용자의 요구사항을 최대한 정확하게 반영하세요.

HTML, CSS, Vanilla JavaScript를 포함한 독립적인 단일 HTML 문서로 출력하세요.

핵심 기능 1~3개를 중심으로 완성도 있게 구현하세요.

모든 주요 버튼과 입력 기능이 실제로 작동하도록 구현하세요.

사용자 요구사항에 디자인 조건이 포함된 경우 이를 충실하게 반영하세요.

외부 API, 개인정보 수집, 실제 결제, 별도 백엔드 기능은 사용하지 마세요.

필요한 경우 가상의 테스트 데이터를 사용하세요.

외부 네트워크 연결 없이 실행될 수 있도록 구현하세요.

출력 형식은 실행 가능한 HTML 코드로 제한하세요.

사용자 요구사항과 무관한 기능을 무분별하게 추가하지 마세요.

## 14. 최종 프롬프트 저장 및 Canva 연계

학생이 완성한 프롬프트를 다음 방식으로 활용할 수 있도록 한다.

- 최종 프롬프트 직접 수정
- 클립보드 복사
- TXT 파일 다운로드
- 브라우저 내 임시 저장
- 기존 작성 내용 불러오기
- Canva AI 바로가기

필요한 경우 다음 내용을 함께 다운로드할 수 있도록 한다.

- 최초 프롬프트
- AI가 발전시킨 프롬프트
- 개선 이유
- 학생이 직접 검토한 최종 프롬프트

Canva AI에 직접 연동하는 별도의 API는 초기 개발 범위에 포함하지 않는다.

학생이 최종 프롬프트를 직접 복사하여 Canva Code에 입력하는 방식으로 진행한다.

## 17. 보안 및 개인정보 보호

중학생이 사용하는 교육 서비스이므로 보안과 개인정보 보호를 중요하게 고려한다.

### API 보안

- LLM API 키는 서버 환경변수에서 관리한다.
- API 키가 브라우저에 노출되지 않도록 한다.
- 사용자 입력을 서버에서 검증한다.
- 부적절하거나 위험한 요청에 대한 입력 및 출력 검증을 적용한다.
- 수업용 접속 코드와 API 요청 횟수 제한을 적용한다.
- 공개 서비스에 대한 무제한 API 호출을 방지한다.
- 전체 수업 단위의 사용량 및 비용 제한을 적용한다.
- 필요시 서버 측 공유형 사용량 제한 저장소를 사용한다.

### 학생 개인정보 보호

- 학생의 실명, 연락처, 주소 등 개인정보 입력을 금지한다.
- 실제 금융정보, 건강정보 등 민감한 정보의 입력을 금지한다.
- 학생의 프롬프트를 서버 로그나 데이터베이스에 불필요하게 저장하지 않는다.
- 외부 LLM 제공자의 미성년자 대상 이용 조건 및 데이터 처리 정책을 사전에 확인한다.
- 학교의 AI 서비스 이용 및 개인정보 보호 정책을 준수한다.
- 생성된 앱에서 개인정보를 수집하지 않도록 한다.

### AI 생성 코드 실행 보안

- AI가 생성한 HTML 및 JavaScript는 신뢰할 수 없는 코드로 취급한다.
- 생성된 코드를 메인 페이지 DOM에서 직접 실행하지 않는다.
- iframe 샌드박스를 적용한다.
- iframe에 allow-same-origin과 allow-scripts를 함께 부여하지 않는다.
- 부모 페이지 접근을 제한한다.
- 외부 네트워크 요청을 제한한다.
- 팝업, 페이지 이동, 폼 전송을 제한한다.
- 브라우저 저장소 및 민감한 기능 접근을 제한한다.
- CSP 등 추가 보안 정책을 적용한다.
- 과도한 연산이나 무한 반복문에 따른 브라우저 문제를 고려한다.
- 필요시 별도의 실행 출처 및 추가적인 격리 방식을 적용한다.

iframe만으로 모든 보안 문제가 해결된다고 가정하지 않는다.

실제 수업 전 생성 코드의 안전성과 브라우저 실행 환경을 검증한다.

## 18. 성능 및 동시 접속 고려

한 학급 약 30명의 학생이 동시에 실습하는 환경을 고려한다.

### 기본 LLM 호출 구조

학생 1명당 다음 API 요청이 발생한다.

- 프롬프트 개선: 1회
- 최초 프롬프트 웹앱 생성: 1회
- 개선된 프롬프트 웹앱 생성: 1회

학생 30명 기준 최초 실습에 총 90회의 주요 LLM 요청이 발생할 수 있다.

추가 질문, 수정, 재생성 요청은 별도로 고려한다.

강사용 Level 1~3 비교 결과물과 진로별 사례는 사전에 생성하여 수업 중 API 호출을 발생시키지 않도록 한다.

### 성능 최적화

- 두 웹앱 생성 요청의 병렬 처리
- API 요청 횟수 제한
- 중복 요청 방지
- 생성 중 버튼 비활성화
- 생성 단계별 진행 상태 표시
- 요청 타임아웃 및 재시도 처리
- 입력 및 출력 토큰 한도 설정
- 전체 수업 단위 API 비용 제한
- API 제공사의 동시 요청 및 사용량 한도 확인
- 실제 학급 규모의 사전 부하 테스트

### 오류 및 예외 처리

Before와 After 중 하나의 생성이 실패한 경우 성공한 결과물을 유지한다.

실패한 결과물만 다시 생성할 수 있도록 한다.

프롬프트 개선에 성공하고 웹앱 생성에 실패한 경우에도 개선된 프롬프트를 저장할 수 있도록 한다.

생성 시간이 길어질 경우 학생이 개선 이유를 먼저 읽거나 최종 프롬프트를 검토할 수 있도록 한다.

수업 중 API 장애나 생성 지연이 발생할 경우 사전에 준비된 비교 사례를 활용해 교육을 진행할 수 있도록 한다.

실시간 결과물 생성은 교육 효과를 높이는 핵심 기능이지만 해당 기능의 장애로 전체 수업이 중단되지 않도록 설계한다.

## 19. 차시별 교육 구성

### 1차시 — 아이디어를 프롬프트로 (60분)

**주제**

좋은 프롬프트 작성법을 학습하고 AI와 함께 자신의 아이디어를 구체화한다.

**시간 구성**

- 5분: Prompt Lab 소개 및 웹사이트 체험
- 5분: 바이브 코딩 제작 사실 및 실제 개발 과정 공개
- 10분: 프롬프트 작성의 5가지 핵심 요소 학습
- 10분: 강사의 Level 1, Level 2, Level 3 결과물 비교 시연
- 5분: 진로별 앱 제작 아이디어 탐색
- 10분: 학생별 최초 프롬프트 작성 및 AI 개선
- 10분: Before & After 미니 웹앱 생성 및 비교 체험
- 5분: 최종 프롬프트 수정 및 저장

**학생 활동**

학생은 프롬프트 작성법을 학습한 후 자신의 관심 분야와 관련된 앱 아이디어를 직접 서술한다.

AI가 개선한 프롬프트와 최초 프롬프트를 비교하고 어떤 부분이 달라졌는지 확인한다.

이후 각각의 프롬프트를 기반으로 생성된 웹앱을 직접 체험한다.

결과물의 차이를 바탕으로 자신이 원하는 앱의 조건을 다시 생각하고 최종 프롬프트를 수정한다.

**1차시 최종 결과물**

- 학생이 직접 작성한 최초 프롬프트
- AI와 함께 발전시킨 프롬프트
- 프롬프트 개선 이유
- 두 개의 비교용 미니 웹앱
- 학생이 직접 검토한 최종 개발 프롬프트

API 장애 등의 상황에서는 미니 웹앱 생성 없이도 최종 프롬프트를 완성할 수 있도록 한다.

### 2차시 — 프롬프트를 실제 앱으로 (60분)

**주제**

자신이 작성한 프롬프트를 활용하여 Canva Code로 앱을 제작하고 친구들과 결과물을 공유한다.

**시간 구성**

- 5분: 이전 차시 복습 및 최종 프롬프트 확인
- 10분: Canva Code 사용법 및 강사 제작 시연
- 15분: 학생별 웹앱 제작
- 10분: 결과물 테스트 및 추가 수정 프롬프트 작성
- 15분: 학생 간 결과물 공유 및 체험
- 5분: 진로 연계 및 학습 성찰

**학생 활동**

1차시에서 완성한 프롬프트를 Canva Code에 입력하여 자신만의 앱을 제작한다.

결과물이 자신이 의도한 기능과 디자인을 충족하는지 확인한다.

부족한 부분은 구체적인 추가 프롬프트를 통해 개선한다.

친구들과 결과물을 공유하며 서로 다른 관심 분야와 프롬프트 작성 방식을 확인한다.

**2차시 최종 결과물**

- Canva Code로 제작한 실제 작동하는 웹앱
- 최초 및 최종 프롬프트
- 추가 수정 프롬프트
- 결과물 검증 및 개선 경험
- 자신의 미래 진로에서 AI를 활용하는 방법에 대한 이해

### 추가 수정 프롬프트 교육

막연한 수정 요청과 구체적인 수정 요청의 차이를 설명한다.

**막연한 요청**

더 예쁘게 만들어줘.

**구체적인 요청**

배경을 흰색으로 변경하고 주요 버튼을 파란색으로 통일해줘.

**막연한 요청**

오류 고쳐줘.

**구체적인 요청**

운동 기록을 삭제했는데 총 운동 시간이 변경되지 않아. 기록을 삭제하면 총 운동 시간과 목표 달성률도 다시 계산해줘.

**막연한 요청**

다시 만들어줘.

**구체적인 요청**

기존 기능은 유지하면서 모바일 화면에서 글씨가 잘 보이도록 크기와 버튼 배치를 수정해줘.

학생이 첫 번째 프롬프트뿐만 아니라 결과를 확인한 후 구체적으로 피드백하는 역량도 학습하도록 한다.

## 20. 결과물 나눔 및 진로 연계

2차시 마지막에는 학생들이 직접 만든 앱과 프롬프트를 친구들과 공유한다.

복잡한 온라인 갤러리 시스템을 별도로 구축하지 않는다.

학교에서 허용한 Canva 공유 방식, 기존 학급 공유 공간 또는 학생의 화면을 활용한다.

### 학생 발표 내용

- 내가 관심 있는 직업 또는 분야
- 내가 해결하고 싶었던 문제
- 제작한 앱의 핵심 기능
- 최초 프롬프트와 최종 프롬프트의 차이
- AI와 함께 개선한 내용
- 실제 결과물에서 발견한 문제점
- 미래에 AI를 활용하고 싶은 방법

앱의 화려함이나 기능 개수만으로 학생의 결과물을 평가하지 않는다.

자신의 생각을 명확하게 표현했는지, AI의 결과물을 직접 확인했는지, 부족한 부분을 개선하려 했는지를 중심으로 살펴본다.

- 실제 개인정보가 포함된 부적절한 입력

이미 좋은 프롬프트를 불필요하게 변경하거나 AI가 학생의 원래 의도를 훼손하지 않는지 검증한다.

## 23. 최종 개발 원칙

본 웹사이트의 핵심은 AI가 학생을 대신하여 프롬프트를 작성하는 것이 아니다.

학생이 자신의 생각을 자유롭게 표현하고, 직접 좋은 프롬프트를 작성하고, 필요한 경우 AI와 협업하여 더욱 발전시킬 수 있도록 하는 것이다.

좋은 프롬프트는 단순히 길고 전문적인 표현이 많은 프롬프트가 아니다.

자신이 원하는 목적과 결과, 필요한 기능, 구체적인 조건을 명확하게 전달할 수 있는 프롬프트다.

AI를 활용한 개선 과정은 기존 프롬프트의 부족한 부분을 보완하기 위한 것이며, 학생의 아이디어를 대체하기 위한 것이 아니다.

최초 프롬프트와 개선된 프롬프트의 결과물 차이가 크지 않더라도 학생이 처음부터 좋은 프롬프트를 작성했다는 긍정적인 학습 결과로 해석할 수 있다.

비교 결과를 조작하거나 AI가 개선한 프롬프트가 항상 우수하다는 결론을 강제하지 않는다.

학생이 직접 결과물을 확인하고 판단하는 과정을 가장 중요하게 고려한다.

짧은 수업 시간 안에 누구나 쉽게 이용할 수 있도록 기능과 콘텐츠는 간결하게 유지한다.

다만 디자인과 핵심 기능의 완성도는 전문적인 상용 웹서비스 수준을 지향한다.

불필요한 기능을 추가하기보다는 교육 목적에 직접적으로 기여하는 기능을 우선적으로 개발한다.

### 최종 교육 메시지

AI 시대에는 단순히 AI에게 질문하는 능력만 필요한 것이 아니다.

자신이 원하는 결과를 구체적으로 생각하고, 이를 명확하게 설명하고, AI가 만든 결과를 직접 검증하고, 필요한 부분을 개선하는 능력이 중요하다.

이러한 역량은 개발자뿐만 아니라 어떤 직업을 선택하더라도 활용할 수 있다.

Prompt Lab은 학생들이 이러한 역량을 직접 경험하고 자신의 미래 진로에 적용할 수 있도록 돕는 서비스다.

**좋은 질문에서 시작하여, 나만의 아이디어를 현실로.**
